# Отчёт по системному (E2E) тестированию

**Проект:** Lazy Lecture — сервис расшифровки лекций (audio → text)

**Дата:** -

**Команда:** quality-software-development

> Документ продолжает курсовую работу №3 по дисциплине «Технологии разработки качественного программного обеспечения».

---

## 0. Введение

**Цель документа:** предоставить описание сценариев end-to-end (E2E) тестирования проекта «Lazy Lecture», включающее перечень пользовательских сценариев, используемые инструменты, техники и порядок прогона. Документ предназначен для согласования и дальнейшей реализации/расширения автоматизации E2E-тестирования.

**Область применения:** E2E-тестирование охватывает проверку сквозных пользовательских потоков в web-приложении «Lazy Lecture» во взаимодействии клиентской части (Vue/Quasar SPA) и backend-микросервисов (`api`, `worker`, RabbitMQ, PostgreSQL). Каждому пользовательскому сценарию присвоен формальный код вида **E2E-NNN** для трассировки требований.

## 1. Описание выполненной работы

### 1.1 Объект тестирования

Системное (end-to-end) тестирование проверяет готовый продукт по бизнес-сценариям в окружении, максимально приближённом к production. Тестируется веб-фронтенд во взаимодействии со всеми бэкенд-сервисами:

| Компонент | Реальный | Состояние в E2E |
|-----------|----------|-----------------|
| Web UI (`web-ui`, Quasar SPA) | да | браузер Chrome/Electron, hash-routing |
| REST API (`api`, FastAPI :8000) | да | реальный бинарник в Docker |
| PostgreSQL | да | в Docker; миграции Alembic применены |
| RabbitMQ | да | в Docker, очередь `task_queue` |
| Worker (Whisper) | частично | поднят, но в part E2E-тестах его выход мокируется (`cy.intercept` на `/transcript`) — иначе расшифровка занимала бы >10 мин |
| Telegram-бот | нет | E2E-сценарии бота — отдельный набор pytest-тестов в `bot/tests` (unit-моки aiogram) |

### 1.5 Классификация тестов

#### По уровню изоляции

E2E-тесты Lazy Lecture обеспечивают **минимальную изоляцию**: реальные веб-сервер, API, БД, очередь, реальные миграции и реальный auth-stack. Подменяются только два «тяжёлых» класса эндпоинтов через `cy.intercept`:

| Эндпоинт | Зачем мокируется |
|----------|------------------|
| `GET /transcript?task_id=*` | Worker может расшифровывать лекцию минуты-часы; в E2E подменяем результат фиктивными чанками, чтобы не ждать |
| `POST /upload-audiofile` | В части тестов (`single_task_limit`, `transcription_history`) подменяется, чтобы детерминированно управлять `task_id`; в `happy_path` тоже мокируется |
| `GET /transcriptions?page=...` | Мокируется в тестах, фокусирующихся на UI-логике; в auth/registration сценариях — реальный |
| `POST /auth/register`, `/auth/login`, `/auth/info`, `/auth/patch` | **Реальные** — через `cy.request` в команде `registerAndPrepareUser` |

#### По подходу к тестированию

| Подход | Применение |
|--------|------------|
| **Чёрный ящик** (black-box) | Все сценарии — взаимодействие с UI как пользователь: клики, ввод в поля, drag-and-drop файла, проверка отображённого текста |

| Штатный сценарий (позитивный) | 7 | happy-path расшифровки, история, навигация, успешная регистрация, повторный вход, deep-link |

#### E2E-001 — Регистрация с валидацией и авто-логином

**Краткое описание:** проверка пользовательской регистрации через форму, валидации полей и автоматической авторизации после успешного создания учётной записи.

**Цель:** убедиться, что новые пользователи могут зарегистрироваться, ошибки валидации обрабатываются корректно и при успешной регистрации происходит автоматический вход.

**Триггеры:**
- пользователь открывает страницу регистрации;
- пользователь заполняет форму и нажимает «Зарегистрироваться».

**Контекст:** веб-приложение с фронтом на Vue.js (Quasar) и бэкендом на FastAPI; используется Cypress для E2E.

**Предусловия:**
- тестовый API доступен;
- эмуляция пустой базы пользователей (или гарантированно уникальный логин через `generateLatinUsername()`);
- скорость сети достаточна для ответов ≤ 5 сек.

**Шаги и ожидаемое поведение:**

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Открыть `/sign_up`. | Отображаются поля «Логин» и «Пароль». |
| 2 | Ввести логин, пароль оставить пустым. Submit. | Сообщение «Введите пароль». |
| 3 | Ввести пароль, логин оставить пустым. Submit. | Сообщение «Введите логин». |
| 4 | Логин `ValidLogin`, пароль `short`. Submit. | Тултип «Password must be 8-256 characters». |
| 5 | Логин `ru`, пароль `GoodP@ss123`. Submit. | Тултип «Username must consist of…». |
| 6 | Логин `<random>`, пароль `GoodP@ss123456#Aa`. Submit. | HTTP 200 в ≤ 5 сек, авто-редирект на `/transcripts`. |
| 7 | Перезагрузить `/transcripts`. | Пользователь остаётся авторизованным, нет редиректа на `/log_in`. |
| 8 | Зарегистрироваться с уже существующим логином. | Тултип «Пользователь уже существует». |

**Постусловия:**
- новый пользователь создан в БД;
- токен сохранён в `localStorage`, пользователь авторизован.

**Сценарий отказа:** существующий логин → 400 Bad Request с сообщением «Пользователь уже существует».

#### E2E-002 — Happy-path: Web → API → Worker → Web

**Краткое описание:** полный путь загрузки аудио, обработки на сервере и отображения результата пользователю.

**Цель:** проверить интеграцию фронта, API и фонового воркера, включая прогресс-бар и экспорт результата.

**Триггеры:** авторизованный пользователь нажимает «Загрузить аудио».

**Контекст:** Cypress с перехватом API-запросов (`cy.intercept`) для эндпоинтов worker-результатов.

**Предусловия:**
- у пользователя `can_interact = true` (через `cy.registerAndPrepareUser`);
- загружаемый файл: `sample_19m57s.mp3` (≈20 мин, < 200 МБ).

**Шаги:**

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Логин → `/log_in` → submit. | Редирект `#/transcripts`. |
| 2 | Выбрать `sample_19m57s.mp3` через `<input type="file">`. | Файл появился в списке uploader'а. |
| 3 | Нажать `i.q-icon=cloud_upload`. | API возвращает `{task_id: 1}`, редирект `#/transcripts/1`. |
| 4 | Дождаться `@chunksReq`. | Прогресс-бар обновляется (мокаются метки 15-минутных блоков). |
| 5 | После 100% — статус «completed», запись попадает в историю. | Список истории обновился. |
| 6 | Клик по записи → открыть `#/transcripts/1`. | Видны 2 чанка с ожидаемым текстом, пустые скрыты. |
| 7 | Нажать «Экспорт в TXT». | Скачан `Транскрипция №1.txt` с текстом обоих чанков. |

**Постусловия:** транскрипция сохранена на сервере; пользователь может скачать результат.

#### E2E-003 — Ограничение одной задачи и отмена

**Краткое описание:** проверка поведения системы при попытке запустить более одной транскрипции одновременно и возможности отменить текущую задачу.

**Цель:** убедиться, что одновременно обрабатывается не более одной задачи и отмена работает корректно.

**Триггеры:** пользователь загружает несколько файлов подряд.

**Предусловия:**
- пользователь авторизован;
- первая задача в состоянии `queued` или `in_progress`.

**Шаги:**

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Загрузить файл A. | Статус `queued`/`in_progress`. |
| 2 | Не дожидаясь завершения A — загрузить файл B. | API → `400 {"detail":"Already processing transcription."}`; toast «Нельзя загрузить: уже обрабатывается другое аудио.» |
| 3 | На экране прогресса нажать «Отменить обработку» для A. | Статус → `cancelled`, частичные результаты сохраняются. |
| 4 | Загрузить файл B повторно. | Принят успешно, статус `queued`, переход на `#/transcripts/2`. |

**Постусловия:** первая задача отменена; вторая обрабатывается без ошибок.

**Сценарий отказа:** сбой при отмене (`POST /cancel` возвращает 5xx) → отображается уведомление «Не удалось отменить задачу».

#### E2E-004 — История транскрипций и просмотр чанков

**Краткое описание:** проверка списка предыдущих транскрипций, навигации по чанкам и скрытия пустых блоков.

**Цель:** убедиться, что пользователь видит до 100 последних заданий, может открыть любую и перейти к нужному чанку.

**Предусловия:** у пользователя есть несколько завершённых транскрипций.

**Шаги:**

| Шаг | Действие | Ожидаемый результат |
|-----|----------|---------------------|
| 1 | Авторизоваться, открыть меню «История». | Список из 2 транскрипций в порядке убывания даты. |
| 2 | Кликнуть по задаче A. | Загрузка чанков A, отображение только непустых. |
| 3 | Нажать на метку прогресса для второго чанка. | Страница прокручивается к `#chunk-2`. |

**Постусловия:** пользователь видит текст только непустых чанков; навигация по меткам корректно переносит к блоку.

#### E2E-005 — Ограничения аудио: длина, формат, размер

**Краткое описание:** проверка ошибок при загрузке аудиофайлов с неподходящими параметрами и нормального потока при корректном файле.

**Цель:** убедиться, что валидация на фронте и API блокирует неподдерживаемые аудио.

**Предусловия:**
- пользователь авторизован;
- файлы-фикстуры: `too_short.mp3`, `too_long.mp3`, `invalid_format.wav`, mp3 > 200 МБ (генерируется на лету), валидный `sample_19m57s.mp3`.

**Шаги:**

| Шаг | Файл / условие | Ожидаемый результат |
|-----|---------------|---------------------|
| 1 | `too_short.mp3` (< 10 c) | Toast «Длина аудио должна быть больше 10 секунд.» |
| 2 | `too_long.mp3` (> 2 ч) | Toast «Длина аудио должна быть меньше 2 часов.» |
| 3 | `invalid_format.wav` | Файл не добавляется в список загрузки (`.q-uploader__file` пуст). |
| 4 | mp3 > 200 МБ (in-memory `ArrayBuffer`) | Toast «Размер аудио должен быть меньше 200 Мбайт.» |
| 5 | Корректный `sample_19m57s.mp3` | Переход на экран прогресса, отображение транскрипта. |

**Постусловия:** недопустимые файлы заблокированы; корректный файл обработан по основному сценарию.

|------|-----------|

## 5. Процедура расширения E2E-набора

При появлении новой пользовательской фичи (например, поделиться транскрипцией по ссылке `/share/{id}`):

1. Создать новый spec `web-ui/cypress/e2e/share.cy.js`.
2. Использовать `cy.registerAndPrepareUser()` для подготовки пользователя через реальный API.
3. Подменить только заведомо медленные эндпоинты (`GET /transcript?task_id=*` и подобные) через `cy.intercept`.
4. Описать ровно один бизнес-сценарий на тест: «Создать транскрипцию → получить share-ссылку → открыть её в инкогнито (`cy.session()`) → проверить публичный доступ».
5. Добавить запись в этот документ (раздел 2.1) и негативный кейс (например, `/share/{невалидный_id} → 404`).
6. Прогнать локально через `npx cypress run --spec cypress/e2e/share.cy.js` против поднятого `docker compose`.

**Шаблон:**

```js
/* eslint-disable */
/// <reference types="cypress" />
import { generateLatinUsername } from '../support/utils';

const username = generateLatinUsername();
const password = 'GoodP@ss123456#Aa';
const apiUrl   = Cypress.env('apiUrl');

describe('N️⃣ Поделиться транскрипцией публичной ссылкой', () => {
  before(() => {
    cy.registerAndPrepareUser(username, password);
  });

  it('🧪 Хозяин создаёт share-ссылку, аноним открывает её и видит чанки', () => {
    cy.intercept('GET', `${apiUrl}/transcript?task_id=1*`, { fixture: 'shared_chunks.json' }).as('chunks');

    // авторизация
    cy.hashVisit('/log_in');
    cy.get('[data-test="ui-testing-auth-page-login-input"]').type(username);
    cy.get('[data-test="ui-testing-auth-page-password-input"]').type(password);
    cy.get('[data-test="ui-testing-auth-page-submit-btn"]').click();
    cy.location('hash').should('include', '#/transcripts');

    // действие — создание share-ссылки
    cy.hashVisit('/transcripts/1');
    cy.contains('Поделиться').click();
    cy.get('[data-test="ui-testing-share-link"]').then($el => {
      const url = $el.text();
      // открыть в новой сессии без cookie/localStorage
      cy.session('anonymous', () => {});
      cy.visit(url);
      cy.wait('@chunks');
      cy.contains('текст первого чанка').should('be.visible');
    });
  });
});
```

При появлении нового потока бота — отдельный набор pytest-тестов в `bot/tests/` (не Cypress).
